# TypeScript Patterns I Wish I Learned Earlier

After years of TypeScript in production, these are the patterns that made the biggest difference.

## 1. Discriminated Unions Over Optional Fields

**Before:**
```typescript
interface ApiState {
  loading: boolean;
  data?: User;
  error?: string;
}
```

**After:**
```typescript
type ApiState =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; data: User }
  | { status: "error"; message: string };
```

The discriminated union forces you to handle every case. The type narrowing in `if` blocks is automatic. No more `data?.user?.name ?? ''` chains.

## 2. `satisfies` for Config Objects

```typescript
const THEME = {
  colors: {
    cyan: "#00d4ff",
    green: "#00ff41",
  },
  spacing: {
    sm: 8,
    md: 16,
  }
} satisfies Record<string, Record<string, string | number>>;

// THEME.colors.cyan is still typed as "#00d4ff", not string
```

`satisfies` validates the shape without widening the type. You get both safety and specificity.

## 3. Template Literals for Route Types

```typescript
type Section = "about" | "skills" | "projects" | "contact";
type NavHref = `#${Section}`;

const link: NavHref = "#skills"; // ✓
const bad: NavHref = "#random";  // ✗ Type error
```

Eliminates entire categories of string typos in navigation and routing code.

## 4. `infer` for Library Wrapper Types

```typescript
type UnpackPromise<T> = T extends Promise<infer U> ? U : T;
type ResolvedGitHubStats = UnpackPromise<ReturnType<typeof fetchGitHubStats>>;
```

Instead of manually maintaining return type definitions for async functions, derive them.

## 5. Const Assertions + Utility Types

```typescript
const SKILLS = ["Python", "TypeScript", "Rust"] as const;
type Skill = (typeof SKILLS)[number]; // "Python" | "TypeScript" | "Rust"
```

The `as const` makes the array immutable and narrows the types to literals. Combined with indexed access types, you get derived union types from data definitions — your single source of truth.

---

These five patterns collectively eliminated about 30% of the type-related code reviews I used to write. TypeScript is most powerful when the types derive from data, not the other way around.
